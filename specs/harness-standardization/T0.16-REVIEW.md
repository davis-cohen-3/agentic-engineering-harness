**Requested explicitly by the developer** for this wave, notwithstanding CONTRACT §6's standing
rule that no reviewer runs automatically. Wave 0 earns the exception: it authors the installer
that overwrites a machine-wide tree, the guards that gate every edit in every adopting repo, and
the review machinery itself.

**Scope:** `git diff 92bac8e..HEAD` — 19 commits, 326 files, excluding
`specs/harness-standardization/snapshot/` (a verbatim forensic copy, not authored code).
**Reviewers:** `reviewer` and `reviewer-security`, run separately.

## Fixed — security

### S1 · CRITICAL · `*** Move to:` rename destinations bypassed the secret guard
`adopt/hooks/protect-secrets.sh`

The path extractor parsed only `*** Add|Update|Delete File:`. Codex's `apply_patch` grammar has a
fourth path-bearing directive, `*** Move to:`, used to rename-on-edit. The **destination of a
rename was therefore never path-checked**: an agent could write an innocuous file and move it onto
`.env` or `deploy/id_rsa`, and the guard returned **exit 0**.

Verified independently, not taken on report: `strings` on the installed `codex 0.147.0` binary
lists all four directives. Reproduced both exploits at exit 0; both are exit 2 after the fix, and
an ordinary edit still exits 0.

**Why T0.11 missed it.** The payload model was built from 118 *observed* `apply_patch` calls in
`~/.codex/sessions`, none of which happened to be a rename. Observed traffic is not the grammar.
That is a methodology error, not a transcription slip, and it is the reason this task existed.

**This is a deliberate deviation from verbatim harvest.** Melting's `origin/main` blob
`7687e47a…` has the identical gap. The deviation is recorded in the script header, and
**melting needs the same fix** — tracked as a Wave 2 item below.

Also hardened in the same expression: a leading-whitespace tolerance, so an indented header cannot
slip the `^` anchor.

### S2 · HIGH · Two hooks broke their own exit-code contract on malformed stdin
`adopt/hooks/block-default-branch-commit.sh`, `adopt/hooks/flag-comment-bloat.sh`

Both carried `set -e`, so a failing `jq` aborted the script before its own `exit 0`, returning
jq's **exit 5** — neither the documented 0-allow nor 2-block. Codex's handling of a third code is
listed in CONTRACT §5 as an untested dependency, so the behaviour was undefined in practice.
`block-default-branch-commit.sh` is the higher-stakes case: it gates `git commit`/`git push`.

Six of the eight hooks already omitted `-e` for exactly this reason. Fixed by matching them, with
a note in each explaining why `-e` is absent so it does not get "helpfully" restored.

**Now asserted for every hook, not just these two:** `hooks.test.sh` feeds truncated JSON to
`adopt/hooks/*.sh` and requires 0 or 2 from each. A new hook is covered automatically.

## Fixed — correctness

### C1 · MUST · `.claude/active-spec` was committed, not retired
T0.13 removed the `.gitignore` entry but not the file. Un-ignoring it meant the next `git add -A`
**versioned the retired surface** — leaving it more present than before the task, and the commit
message said it had been removed. That was false.

Every assertion meant to catch it missed: the `.gitignore` grep asserted the ignore entry was gone
(the very change that caused it), the retired-convention scanner skipped extension-less files, and
`workspace.test.sh` checks a sandbox worktree rather than this repo. Now asserted directly —
absent from disk **and** untracked in the index.

### C2 · MUST · The harness repo's own Stop gate never fired
`adopt/hooks/enforce-gate-on-stop.sh` guarded on `grep -q '^check:' Makefile`. This repo's root
`Makefile` is three lines ending in `include adopt/Makefile` and has no literal `check:` recipe, so
the guard failed and the hook exited 0 **unconditionally**. Reproduced: with the gate forced red,
the hook still allowed the stop. `AGENTS.md` and CONTRACT §6 both claim the gate is hook-enforced;
here it was not. Adopted repos were unaffected (they get `adopt/Makefile` verbatim).

Fixed by **resolving** the target — `make -n check` — instead of matching text. The existing test
passed because it *replaced* the Makefile with a literal recipe, exercising a shape this repo does
not use; it now also covers a gate reachable only through an `include`.

### C3 · MUST · The `apply_patch` matcher assertion was theatre
`test/adopt.test.sh` grepped the whole of `.codex/hooks.json` for `apply_patch` — satisfied by the
*comment-bloat* matcher on another line. Proven by mutation: removing `apply_patch` from
protect-secrets' own matcher — precisely the CONTRACT §5 failure mode, where the guard silently
never runs on a Codex edit — left **all three suites green**. Now asserted per-matcher: find the
group whose hooks include `protect-secrets.sh`, and require `apply_patch` in *that* matcher.

### C4 · `wt` run from inside a worktree nested `worktrees/worktrees/`
`git rev-parse --show-toplevel` returns the *current* worktree. Since `code/` is only a reference
checkout, running `wt` from a worktree is the **normal** case — and it recreated exactly the nested
mess decision B exists to clean up, while also missing the registry lookup. Fixed by resolving the
main checkout via `--git-common-dir`. Covered by a new `workspace.test.sh` case.

### C5 · A relative `worktree_root` silently half-created a worktree
`git -C "$REPO" worktree add` resolves a relative path against the repo; every later check resolved
it against the caller's cwd. Result: the worktree landed where nothing else looked, `.workspace/`
and `make setup` were both skipped, and `wt` **exited 0**. Fixed by absolutising `ROOT` before
anything consumes it. Covered.

### C6 · `test/install.test.sh` pinned `HOME` but not `XDG_CONFIG_HOME`
*Found during my own pass, not by either reviewer.* `install.sh` resolves the registry through
`${XDG_CONFIG_HOME:-$HOME/.config}`. On any machine or CI where that variable is set, the
sandboxed installer test would read the real depot registry and **write the real
`~/.config/agents/projects.yaml`** — the file Wave 1 T1.6 owns. Dormant here only because the
variable happens to be unset. Same class as the incident that cut two real worktrees. Both runners
now pin it.

## Fixed — coverage and consistency

- **Depot was never exercised** in the acceptance scenario, though CONTRACT §7 names it one of the
  three creators. Added steps C4–C5, including the observable that matters: `MISSION.md` exists in
  a Depot-created worktree, and **Depot did not create it** (CONTRACT §1) — the SessionStart net
  did.
- **This repo had no `.codex/hooks.json`.** The one repo where a hook regression costs most was
  Claude-only for hooks, while every adopted repo gets both bindings. Added, pointing at
  `adopt/hooks/` (the harness consumes its own payload), validated by `make check`, and asserted to
  resolve and to carry `apply_patch` on protect-secrets' matcher.
- **`adopt/docs/` had no contract entry.** CONTRACT §4 defines the `docs/` layout but §5's `adopt/`
  tree did not list it, making it the only payload item with no written owner. Added to §5.
- **`install.sh --force` was undocumented.** It is a destructive escape hatch on the one refusal
  that prevents unrecoverable loss. Now stated in CONTRACT §5.
- **`adopt/AGENTS.template.md`** was missing DECISION E ("no reviewer runs automatically") and the
  `verify-before-done` ownership pointer that the harness's own `AGENTS.md` carries. Added.
- **Wave 1 T1.3 was predicted, never measured.** Re-measured read-only: `--dry-run` refuses **8**
  files, not two, and reports `keep 4` including `grill-me` and `overview-fresh` — both retired by
  CONTRACT §5, so **T1.3 must run `--prune`** or T0.6's collapse never reaches the machine. The
  plan now carries the measured list and per-file disposition.

## Accepted, not fixed

| # | Finding | Why it is accepted |
| --- | --- | --- |
| A1 | `mv "$staging" "$DEST"` is atomic only if `$TMPDIR` and `$HOME` share a filesystem | Dormant here (verified same `st_dev`). If it ever splits, the next run's classifier catches it: missing files become `add`, truncated files become `edited` and refuse. Incidental protection rather than designed, and worth revisiting if the harness ever runs on Linux with a tmpfs `/tmp` — but not a Wave 0 blocker. |
| A2 | `~/.agents.prev` is overwritten on every successful run | Matches the documented "keeps ONE backup" design (CONTRACT §5). Verified: recoverable after one run, permanently gone after two. Behaviour is intended; the risk is an operator running twice while still meaning to recover. |
| A3 | `rels()` uses `find -type f`, so symlinks are invisible to the drift accounting | `core/` and `adopt/` ship no symlinks, and the install manifest is built from the same walk, so source and record agree. Real gap only if the payload ever gains one. |
| A4 | `~/.agents` being a symlink is not special-cased | Outside the documented model. Verified non-destructive: `mv`/`rm -rf` on a symlink argument touches only the link. |
| A5 | `*.env.*` blocks `settings.env.example` | Pre-existing, not from this diff, and a false *positive* on a guard — it refuses a safe file rather than allowing an unsafe one. Correct direction to fail. |
| A6 | The provenance assertion greps the file for a SHA its own author wrote | It is a marker, not proof. The blob was verified out-of-band against melting twice — by me during T0.11 and independently by the reviewer — and both confirmed byte-identity. Re-fetching melting inside `make check` would make the gate depend on another repo being present. |
| A7 | `migrate-registry.py` assumes `projects:` is the last top-level key and `repo:` precedes `worktree_root:` | Both hold in the real file and the migration is a one-time Wave 1 step whose output is diffed by hand before activation. Noted so the diff is actually read. |
| A8 | A Codex binding outside a git repo expands to `/.claude/hooks/…` → exit 127 | Cannot occur for a repo-owned hook, which by definition only fires inside its repo. Whether Codex treats 127 as allow is worth confirming in Wave 1 T1.9 alongside the other provider behaviours. |

## Follow-up pass — the accepted findings, revisited with the developer

Walked one by one on 2026-08-09. Six were fixed after all; three stand as accepted, now by
explicit decision rather than by default.

| # | Was | Now |
| --- | --- | --- |
| A1 | staging under `$TMPDIR`; swap atomic only by luck | **Fixed** — stages under `$HOME`, atomic by construction |
| A2 | `~/.agents.prev` discarded silently | **Fixed** — warns before replacing the only backup |
| A3 | symlinks invisible to the drift accounting | **Fixed both sides** — the walk sees them and `cp -Pp` preserves them; a new `validate-payload` gate step forbids one in `core/`/`adopt/`, where publishing a link has no meaning |
| A4 | `~/.agents` as a symlink not special-cased | **Fixed** — refuses, naming the link and its target |
| A7 | registry migration appended at EOF | **Fixed** — inserts inside `projects:`, and refuses a shape it cannot attribute |
| — | manifest parse broke on paths with spaces | **Fixed** — splits on the two-space separator |
| A5 | `*.env.*` blocks `.env.example` | **Accepted, deliberately.** A guard whose job is to be wrong in the safe direction. A false positive costs a sentence; a false negative costs a credential. An `.example` exemption is also trivially gamed by filename. |
| A8 | binding returns 127 if `git` fails | **Accepted, scheduled.** Unreachable outside a repo (a repo-owned config only loads inside it); reachable only with `git` missing *inside* a git repo. Wrapping all seven commands in both binding files to cover it would make the most-read config markedly harder to scan. Wave 1 T1.9 now probes what Codex does with 127. |
| A6 | provenance check greps a SHA its own author wrote | **Accepted, relabelled.** It now says it is a marker, and the script header records that faithfulness was verified out-of-band. Re-checking would make a green gate depend on another repo being present. |

Two test defects surfaced while writing these regressions, both worth naming because they are the
same class T0.16 exists to catch:

- The first space-path test **passed against the broken parser**. An unchanged file matches by hash
  and never reaches `installed_sha`, so the code under test never ran. It now changes the source
  first — the only path that reads the manifest.
- It also leaked state: a sourceless file left as a kept extra shifted the `keep` count every later
  test saw. Cleanup now prunes, and the leak is asserted against.

**Melting's copy is patched, not just reported.**
`patches/melting-protect-secrets-move-to.patch` is a verified, `git apply --check`-clean diff
against `origin/main`, with the exploit and the no-false-positive case both exercised. Applying it
is the developer's action; nothing here does it.

## T0.12's second acceptance line — restated honestly

"A PR body produced from a populated `LOG.md` contains its settled decisions."

What is **automated** is the mechanism: the template carries a `## Decisions` section, `open-a-pr`
instructs the carry, and `ship` delegates rather than duplicating. What was **observed once, by
hand**, is the behaviour: a populated `LOG.md` with two `DECISION` entries and one open `QUESTION`
was transcribed into a PR body, and all three — including both rejected alternatives — appeared.

That is a manual observation, not a regression test, and it is not claimed as one. The behavioural
check belongs to the Wave 2 walk, step **H3**.
